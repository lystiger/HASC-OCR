## Spec gaps I settled

1. **What a Zalo sheet is.** `form = 'BMMT01-2022/HASC'` and `machine = ''` (`intake.is_zalo_sheet`). Website sheets always have a picked machine, so the two never mix.
2. **Written machine on a Zalo row.** The cell is normalised like the report does (`" t 1 "` is `T1`). A written value that is not `[TM]digit` stays as written, is not carried down and blocks the plan for that row. An unreadable Máy cell counts as blank. A carried-down machine is stored with `inherited = 1` and no doubt.
3. **Where row machines are set.** In the worker, in memory before `_write_result`, so the cells, the doubt flag and the note go in with the read's own write. A plan problem (for example an unreadable `known_names.json`) logs and leaves the rows blank and flagged. It does not fail the read job.
4. **Plan machine outside the report's fixed list** (`MACHINES`): the row goes under "chưa rõ máy" with the note "Máy ghi không rõ: <machine>", so no kilogram is lost.
5. **"Chưa nhận tờ" for Zalo rows.** A machine and shift counts as received when a Zalo row on a `form_a` sheet has that machine. A Zalo back page alone does not, matching the existing rule for website backs. The spec's wording says "a Zalo row"; I kept the existing rule.
6. **The two new summary lines** count all pilot photos in `waiting` and in `delivered` now, not those of one day, because an inbox row has no production date until it is filed. They show when N > 0, also on a day with no data.
7. **Office list link** shows the pilot `waiting` count only (not `not_form`), and only to employee and admin. The page itself lists `waiting` and `not_form`.
8. **Page size** of `/zalo/cho-xep` is 50. The page defaults the date and shift of each form from the photo's send time.
9. **Staging rows** are not listed on `/zalo/cho-xep` and cannot be filed through it (404). Their gate cost is in the AI page cost (it was paid).
10. **AI page.** The daily table gets a token column, because the criterion asks for daily token totals. The download counters count `delivered`, `filed`, `waiting`, `not_form` and `staging_checked`. The inbox card names the new statuses and the staging would-be outcome.
11. **Machine filter.** `?machine=Zalo` selects sheets with machine `''` and the Zalo form. T1/T3/T6 keep their meaning.
12. **Review history labels** for `zalo_filed`, `zalo_resend`, `zalo_back` so no raw event name shows.
13. **Reviewing earlier runs' work.** I read `hasc/intake.py`, `hasc/worker/gate.py`, migration 009, `hasc/plans.py` and the worker wiring against R1-R6 and kept them. The earlier checkpoint's 560 tests plus mine now run as 610.
